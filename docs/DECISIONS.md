# Decisions (Lane 0)

One line per Lane 0 VERIFY item (V1–V8): `V<n>: <what was found> → <what the repo uses>`. Checked on Node 26.13.1 and repeated where noted on Node 22.13.0, the engines floor.

- V1: `ai` 7.0.173 with `@ai-sdk/anthropic` 4.0.105, `createAnthropic({ apiKey })` and a model object (never a bare `provider/model` string), streamed a chat reply through `/api/chat` with only `ANTHROPIC_API_KEY` and `EXA_API_KEY` set and no gateway variable present; repeated from a clean clone on Node 22.13.0 → the repo uses AI SDK 7, no fallback.
- V2: `generateText` with `output: Output.object({ schema })` (zod 4.6.7) returned an object that passed `schema.safeParse` on `claude-haiku-5-5` → structured output uses `output`, no fallback.
- V3: the route sends `status` as `{ type: 'data-status', transient: true }`; driven through `Chat` from `@ai-sdk/react` with `DefaultChatTransport`, the part reached `onData` and was absent from `chat.messages` and from their JSON (what the page saves to `localStorage` and restores on reload), while the other data parts stayed in `messages` (`app/api/chat/route.test.ts`) → transient data part, no fallback. Not exercised in a real browser reload.
- V4: the step cap is `stopWhen: isStepCount(n)` (`stepCountIs` is still exported as an alias). It caps model steps, not tool calls: with `isStepCount(2)` one run made 3 parallel `web_search` calls in step 1 and 2 in step 2, then ended with `finishReason: 'tool-calls'` and no text → Lane 4 allows one step more than the search cap and switches tools off on the last step (`prepareStep` with `activeTools` / `toolChoice`; the Anthropic provider option `disableParallelToolUse` also exists), and Lane 5's `searchMore` cap stays required.
- V5: a static `import { DatabaseSync } from 'node:sqlite'` in a Node-runtime route opened a file database under `next dev` and `next build` + `next start` on both Node 26.13.1 and 22.13.0 (22.13.0 prints `ExperimentalWarning: SQLite is an experimental feature`). FTS5: on 26.13.1 `PRAGMA compile_options` lists `ENABLE_FTS5` and a `MATCH` query works; on 22.13.0 it does not, and `CREATE VIRTUAL TABLE … USING fts5` fails with `no such module: fts5` → plain static import; `fts5: false`, so Lane 2 uses a `LIKE` scan behind the same `MemoryStore` methods, because the engines floor is 22.13.
- V6: the Anthropic models list returned `claude-haiku-5-5` and `claude-sonnet-5-5` as the newest of their tiers, and a one-word request to each succeeded → `config.ts` uses `claude-haiku-5-5` (router, judge, extractor) and `claude-sonnet-5-5` (writer).
- V7: `/search` with `contents.text` returns `results[]` with `id`, `url`, `title`, `text`, and `publishedDate` on some results only (1 of 3 in the probe); `startPublishedDate` is accepted and every result came back on or after it. `/contents` with `maxAgeHours: 0` returns `statuses[]` per URL: `{ id, status: 'success', source: 'crawled' }` for a live crawl, `source: 'cached'` when `maxAgeHours` is omitted, and `{ id, status: 'error', error: { httpStatusCode, tag } }` for a failed URL, which has no entry in `results` → `live` comes from `source === 'crawled'` (confirmed by the provider, not inferred); `publishedAt` is null when `publishedDate` is absent; the provider date filter is used. Raw responses: `src/core/search/fixtures/probe-search.json` (request `{ query, type: 'auto', numResults: 3, contents: { text: { maxCharacters: 3000 } } }`) and `probe-contents.json` (request `{ urls: [one good, one .invalid], text: { maxCharacters: 3000 }, maxAgeHours: 0, livecrawlTimeout: 8000 }`).
- V8: `"type": "module"` works with `next.config.mjs`, the `.mjs` scripts, `tsc`, `vitest`, `next dev` and `next build` → kept.

## Later decisions (18 Nov 2026)

- Duplicate display: the "On <date> you asked: …" line was streamed as answer text and also shown by the recall card. It now appears only in the card. The recalled question and its timestamp stay a structured field on the recall event (`asked`, contract request `docs/contract-requests/recall-asked.md`), so API consumers still get them. The no-record event also carries the `nearest` turns the writer was given.
- Dates stay as `formatLocal` prints them ("Tue 3 Nov 2026"). Eval case 8's "3 November 2026" is our eval's wording, not the challenge brief's, so the format is not changed for it.
- Time zones stay as `formatLocal` prints them (for example "GMT+5:30").
- Evals: the literal number reading skips spans the app itself injects (timestamps, dates and the recall line in code-built lines); see `evals/TRIAGE.md` change 8. Live eval runs are capped by `--budget-usd` (default 4.5).
